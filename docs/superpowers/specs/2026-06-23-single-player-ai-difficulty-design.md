# 单人模式真实难度方案

## Summary
在现有“单人游戏”入口上保留 `2/3/4` 总人数选择，新增一行“游戏难度”，提供 `低 / 中 / 高` 三档，并把该难度统一作用于本局全部 AI（最多 3 个）。
这次只改变 AI 的**决策聪明程度**，不改发牌、得分、道具概率、隐藏信息规则，也不让高难度作弊。整体目标是“三档差异明显，但三档都偏弱，高难度也只是更稳，不是更狠”。

## Key Changes
### 1. 菜单与配置传递
- 在单人对局弹窗中新增一行，顺序固定为：`游戏人数 -> 游戏难度 -> 道具模式 -> 获胜积分`。
- 保留现有 `2/3/4` 总人数选项，难度默认选中 `中`。
- 新增难度文案 key：
  - `PLAYER_COUNT_DIFFICULTY`
  - `PLAYER_COUNT_DIFFICULTY_LOW`
  - `PLAYER_COUNT_DIFFICULTY_MEDIUM`
  - `PLAYER_COUNT_DIFFICULTY_HIGH`
- `MainMenuPlayerCountDialog.StartGameRequested` 扩展为同时回传难度值。
- `GameBoardScene` 新增导出属性 `solo_ai_difficulty`，使用 3 档枚举/整数：
  - `0 = Low`
  - `1 = Medium`
  - `2 = High`
- `StartGameWithOptions(...)` 在单人开局时把该值写入 `GameBoardScene`。
- 不新增存档持久化；表现跟现有弹窗选项一致，仅随当前主菜单场景生命周期存在。

### 2. 难度 UI 与图标
- 现有图标外圈徽章继续沿用 `MainMenuPlayerCountIconBadge.cs` 的圆形底座与描边。
- 用户要求用生图，因此只生成**内层 glyph**，不替换整个徽章：
  - 生成一个透明 PNG，小型“难度等级”符号，视觉方向固定为“海洋科技感的三阶指示 glyph”，白青线稿、轻发光、适合 36x36 圆形徽章中心展示。
  - 集成方式：给 `MainMenuPlayerCountIconBadge` 增加 `Difficulty` 图标分支，中心绘制该 PNG。
- 资源生成顺序固定：
  1. `$generate2dsprite`
  2. `$test-image`
  3. `$rightimage`
  4. 三者都不可用时，**停止实现并报告阻塞**，不做占位图标、不做半成品替代。
- 弹窗行底板样式保持一致：
  - 新难度行必须拥有与现有行同样的槽位框体。
  - 方案固定为：用 `PlayerCountDialogFrameArt` 风格的行框承载第 4 行，必要时把前三行也统一成相同包裹方式，避免第 4 行落在纯背景上。
  - 面板高度向下增大，只做容纳 4 行和按钮的最小增量；按钮底部留白不低于当前体感。

### 3. 单人 AI 规则
- 难度只在**离线单人局**生效，即 `solo_mode == true && !IsNetworkMultiplayerMode()`。
- 冒险模式 AI 不改。
- 网络断线接管 / 网络 AI proxy 不改；如需抽公共 helper，只复用代码，不改变其行为。

#### 3.1 统一结构
- 新增一个轻量 `SoloAiRules/Profile`（结构参考 `EnemyAiRules.AdventureProfile`），把单人 AI 的概率与策略集中管理。
- 三档固定参数如下：

| 难度 | BestCaptureChance | AnyCaptureChance | UsePointScoring | AvoidPairOnlyCaptures |
|---|---:|---:|---|---|
| 低 | 25% | 25% | 否 | 否 |
| 中 | 55% | 20% | 否 | 是 |
| 高 | 78% | 12% | 是 | 是 |

解释：
- `BestCaptureChance`：命中时选“当前最优可吃牌”
- `AnyCaptureChance`：命中时选“任意一个可吃牌”
- 两者都未命中时，不主动抓收益，走现有弱 AI 的非捕获流程

#### 3.2 普通出牌
- 低：
  - 有可吃牌时，只有 50% 总概率会去吃。
  - 没触发吃牌时，保持当前行为：手牌/道具整体随机。
- 中：
  - 有可吃牌时，75% 总概率会去吃。
  - “最优吃牌”按**吃到的张数**优先，不算点数。
  - 避免只拿“纯对子、不中段”的低收益吃牌。
- 高：
  - 有可吃牌时，90% 总概率会去吃。
  - “最优吃牌”按**实际得分**优先，其次按吃牌张数。
  - 同样避免纯对子低收益吃牌。
- 三档都**不做前瞻搜索**、不模拟未来回合、不卡牌记忆，不读额外隐藏信息。

#### 3.3 道具目标选择
- 只改“目标是谁”，不改道具可用性判断。
- `PickItemTargetPlayer(...)`：
  - 低：始终随机合法目标。
  - 中：50% 用策略目标，50% 随机。
  - 高：始终用策略目标。
- 策略目标固定规则：
  - `PlayerHand` 类道具：选**总手牌数最多**的合法对手。
  - `PlayerDeck` 类道具：选**牌堆张数最多**的合法对手。
  - 其他玩家目标类道具：选**当前分数最高**的合法对手。
  - 平局用现有 RNG 打破。
- `PickTargetHandIndex(...)` 保持**随机合法索引**，三档都不允许根据对手隐藏手牌内容做“精准点名”，避免高难度作弊感。

#### 3.4 手牌上限弃牌
- 低：保持随机合法弃牌。
- 中：优先丢弃**分值最低**的普通手牌；若没有普通手牌可选，再随机合法弃置。
- 高：
  - 如果存在“当前不能立刻吃牌”的普通手牌，优先只在这类牌里选。
  - 再从中丢弃分值最低者；平局随机。
  - 若没有可保留的替代牌，回退到中难度逻辑。

#### 3.5 Magnet 附着
- 低：随机附着到一个合法自家手牌。
- 中：附着到**分值最低**的合法自家手牌。
- 高：
  - 优先选“当前没有立即吃牌机会”的合法自家手牌。
  - 再从中挑分值最低者。
  - 若无此类牌，回退到中难度逻辑。

## Test Plan
- 规则测试
  - 固定手牌/桌面/RNG，验证低中高三档在同一局面下能得到**不同且合法**的出牌结果。
  - 验证中/高难度会避开“纯对子低收益吃牌”，低难度不会强制避开。
  - 验证高难度按点数优先选吃牌，中难度按张数优先。
  - 验证目标玩家选择：
    - 手牌目标类选手牌最多者
    - 牌堆目标类选牌堆最多者
    - 通用目标类选当前分数最高者
  - 验证目标手牌索引仍为随机合法索引，不接入隐藏手牌内容判断。
  - 验证中/高难度弃牌与 magnet 附着遵守“低值优先、保留当前可吃牌”的规则。
- 场景/流程测试
  - 扩展 `GameBoardModeRegressionSmoke.gd`，至少覆盖：
    - `solo + low`
    - `solo + high`
    - `4 人单人局 + high`
  - 断言场景可正常开局、AI 可轮转、不死循环、不因新增字段报错。
- UI / 本地化验证
  - 检查单人弹窗在 `zh_CN` 和 `en` 下四行不裁切，开始按钮不被顶出。
  - 跑一次相关布局/截图审计，确认新增难度行和图标在主菜单分辨率下对齐。
  - 校验新增 key 已进入 `ui.csv`；未专门翻译的语种先统一回填英文占位，避免显示裸 key。

## Assumptions
- 单人模式继续表示“1 个真人 + 1~3 个 AI”，对应总人数 `2/3/4`。
- 本局所有 AI 共用同一难度，不做“不同 AI 不同难度”。
- 默认难度为 `中`。
- 冒险模式 AI、联机托管 AI、断线接管 AI 行为保持不变。
- 高难度允许更稳定地抓收益，但不允许偷看对手隐藏手牌内容，也不允许改规则数值。
- 图标资源生成是硬前置；若 `$generate2dsprite`、`$test-image`、`$rightimage` 全不可用，则实现直接停止，不交付无图标替代版本。
